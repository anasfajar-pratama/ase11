1

Soal Praktik — Bangun project Laravel baru dari nol, lalu lengkapi fitur CRUD untuk data mahasiswa hingga aplikasi siap dijalankan. Kerjakan secara berurutan sesuai ketentuan berikut.

Perintah Soal

Buatlah aplikasi pengelolaan data mahasiswa menggunakan Laravel. Aplikasi harus dapat menampilkan daftar mahasiswa serta menambah, mengubah, dan menghapus data. Ikuti langkah-langkah berikut:

a. Instalasi Project

  • Buat project Laravel baru menggunakan Composer dengan nama crud-mahasiswa.
  • Masuk ke folder project, lalu jalankan server development.
  • Pastikan halaman awal Laravel tampil di browser (http://127.0.0.1:8000).

b. Konfigurasi Database

  • Salin file .env.example menjadi .env, lalu buat application key.
  • Atur koneksi database MySQL pada file .env.
  • Buat database kosong di MySQL, misalnya db_crud_mahasiswa.

c. Migration & Model

  • Buat migration tabel mahasiswa dengan kolom: id, nim (unik, maks 20 karakter), nama (maks 100), jurusan (maks 100), email (boleh kosong), angkatan (angka), dan timestamps.
  • Buat Model Mahasiswa dengan protected $fillable yang sesuai.
  • Jalankan migration dan pastikan tabel mahasiswa berhasil dibuat.

d. Routing & Controller

  • Buat controller resource MahasiswaController.
  • Daftarkan Route::resource('mahasiswa', MahasiswaController::class) pada routes/web.php.
  • Lengkapi method: index (menampilkan semua data), create (form tambah), store (simpan), edit (form ubah), update (perbarui), dan destroy (hapus).

e. Validasi

  • Terapkan validasi pada store() dan update(): nim, nama, jurusan, dan angkatan wajib diisi; nim harus unik; serta email (jika diisi) harus berformat email yang valid.
  • Jika validasi gagal, tampilkan pesan error dan pertahankan input sebelumnya menggunakan old().

f. Tampilan (View)

  • Buat view index (tabel daftar mahasiswa + tombol Ubah/Hapus), create, dan edit.
  • Setiap form harus menyertakan @csrf, serta @method('PUT') pada form edit dan @method('DELETE') pada tombol hapus.
  • Tampilkan notifikasi sukses setelah data berhasil disimpan, diubah, atau dihapus.

g. Uji Coba

  • Jalankan aplikasi dan buktikan seluruh fitur CRUD berjalan: tambah, lihat, ubah, dan hapus data mahasiswa.

Kumpulkan: struktur folder project, isi migration, model, controller, route, view, serta screenshot aplikasi yang sudah berjalan.

    $validated = $request->validate([

    ]);

    $mahasiswa->update($validated);

    return redirect()->route('mahasiswa.index')
        ->with('success', 'Data mahasiswa berhasil diubah.');
}

public function destroy(Mahasiswa $mahasiswa): RedirectResponse
{
    $mahasiswa->delete();

    return redirect()->route('mahasiswa.index')

}

Jelaskan apa itu pola MVC pada Laravel, dan sebutkan folder tempat menyimpan Model, View, serta Controller pada project ini.

Jawaban

MVC (Model–View–Controller) adalah pola arsitektur yang memisahkan aplikasi menjadi tiga bagian agar kode lebih rapi dan mudah dirawat:

  • Model → mengurus data dan logika database (Eloquent). Di project ini tersimpan di app/Models/.
  • View → mengurus tampilan (HTML). Di project ini menggunakan Blade dan tersimpan di resources/views/.
  • Controller → menjembatani Model dan View, menerima request lalu mengembalikan response. Tersimpan di app/Http/Controllers/.

Alur request: Route → Controller → Model (ambil/simpan data) → View (tampilkan).

app/
├── Models/            → Mahasiswa.php, Kelas.php, Dosen.php, ...
├── Http/Controllers/  → MahasiswaController.php, JadwalKuliahController.php, ...

resources/
└── views/             → mahasiswa/index.blade.php, mahasiswa/create.blade.php, ...

Apa fungsi Migration? Tuliskan potongan migration untuk membuat tabel mahasiswa minimal dengan kolom nim, nama, dan jurusan.

Jawaban

Migration adalah "kontrol versi" untuk struktur tabel database. Dengan migration, pembuatan tabel dilakukan lewat kode PHP sehingga bisa dijalankan berulang dan konsisten di komputer mana pun (cukup php artisan migrate).

Perintah membuatnya: php artisan make:migration create_mahasiswa_table.

<?php

use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    public function up(): void
    {
        Schema::create('mahasiswa', function (Blueprint $table): void {
            $table->id();
            $table->string('nim', 20)->unique();
            $table->string('nama', 100);
            $table->string('jurusan', 100);
            $table->timestamps();   // created_at & updated_at
        });
    }

    public function down(): void
    {
        Schema::dropIfExists('mahasiswa');
    }
};

Method up() dijalankan saat migrate (membuat tabel), sedangkan down() untuk membatalkan (rollback).

Apa fungsi protected $fillable pada Model? Jelaskan juga cara membuat relasi belongsTo dan hasMany antara Mahasiswa dan Kelas beserta contohnya.

Jawaban

$fillable adalah daftar kolom yang diizinkan diisi secara massal (mass assignment), misalnya lewat Mahasiswa::create($validated). Tujuannya mencegah user mengirim kolom berbahaya yang tidak seharusnya bisa diubah.

Relasi Eloquent menghubungkan antar tabel:

  • belongsTo → sisi "milik" (satu mahasiswa memiliki satu kelas, kolom kelas_id).
  • hasMany → sisi "punya banyak" (satu kelas punya banyak mahasiswa).
// app/Models/Mahasiswa.php
class Mahasiswa extends Model
{
    protected $fillable = ['nim', 'nama', 'jurusan', 'email', 'angkatan', 'kelas_id'];

    public function kelas(): BelongsTo
    {
        return $this->belongsTo(Kelas::class);   // Mahasiswa → Kelas
    }
}

// app/Models/Kelas.php
class Kelas extends Model
{
    public function mahasiswa(): HasMany
    {
        return $this->hasMany(Mahasiswa::class); // Kelas → banyak Mahasiswa
    }
}

Relasi ini bisa dipakai dengan eager loading, contoh di controller: Mahasiswa::with('kelas')->get().

5

Apa yang dihasilkan oleh Route::resource()? Bagaimana cara membatasi aksi tulis (create/store/edit/update/destroy) hanya boleh diakses role admin?

Jawaban

Route::resource otomatis membuat 7 route standar CRUD untuk satu controller (index, create, store, show, edit, update, destroy) sehingga kita tidak perlu menulis route satu per satu.

Route::resource('mahasiswa', MahasiswaController::class);

Menghasilkan route: GET /mahasiswa (index), GET /mahasiswa/create (create), POST /mahasiswa (store), GET /mahasiswa/{id} (show), GET /mahasiswa/{id}/edit (edit), PUT/PATCH /mahasiswa/{id} (update), DELETE /mahasiswa/{id} (destroy).

Untuk membatasi akses, kita pakai middleware. Pada project ini route dipecah dua: index/show cukup auth, sedangkan aksi tulis ditambah role:admin.

Route::middleware('auth')->group(function () {
    Route::resource('mahasiswa', MahasiswaController::class)
        ->except(['index', 'show'])
        ->middleware('role:admin');     // create, store, edit, update, destroy

    Route::resource('mahasiswa', MahasiswaController::class)
        ->only(['index', 'show']);      // boleh dibaca semua user login
});

Dengan cara ini, user role mahasiswa hanya bisa melihat data, sedangkan admin bisa menambah, mengubah, dan menghapus.

Jelaskan alur method store() pada sebuah CRUD, bagaimana validasi dijalankan, dan berikan contohnya. Sertakan juga bagaimana project ini menjaga agar jadwal tidak bentrok.

Jawaban

Method store() menerima data dari form, memvalidasinya, menyimpan ke database lewat Model, lalu mengembalikan response (biasanya redirect).

  • Validasi memakai $request->validate([...]). Jika gagal, Laravel otomatis mengembalikan user ke form beserta pesan error.
  • Rule::unique() memastikan nim tidak duplikat. Saat update dipakai ->ignore($id) agar data miliknya sendiri tidak dianggap duplikat.
  • Redirect dengan pesan memakai ->with('success', '...') untuk ditampilkan di halaman index.
public function store(Request $request): RedirectResponse
{
    $validated = $request->validate([
        'nim'      => ['required', 'string', 'max:20', Rule::unique('mahasiswa', 'nim')],
        'nama'     => ['required', 'string', 'max:100'],
        'jurusan'  => ['required', 'string', 'max:100'],
        'angkatan' => ['required', 'integer', 'min:1900', 'max:2200'],
        'kelas_id' => ['nullable', 'exists:kelas,id'],
    ]);

    Mahasiswa::create($validated);

    return redirect()
        ->route('mahasiswa.index')
        ->with('success', 'Data mahasiswa berhasil ditambahkan.');
}

Validasi bentrok jadwal (pada JadwalKuliahController) adalah validasi tambahan: sebelum menyimpan, sistem mengecek apakah ruangan, dosen, atau kelas sudah terpakai di hari & jam yang sama menggunakan query whereBetween. Jika bentrok, ditolak dengan withErrors().

$bentrokRuangan = JadwalKuliah::where('ruangan_id', $validated['ruangan_id'])
    ->where('hari', $validated['hari'])
    ->where(function ($query) use ($validated) {
        $query->whereBetween('jam_mulai', [$validated['jam_mulai'], $validated['jam_selesai']])
              ->orWhereBetween('jam_selesai', [$validated['jam_mulai'], $validated['jam_selesai']]);
    })
    ->exists();

Apa itu Blade Template? Jelaskan fungsi directive {{ }}, @csrf, @method, dan @forelse. Mengapa @method('PUT') atau @method('DELETE') diperlukan pada form HTML?

Jawaban

Blade adalah engine template bawaan Laravel. Kita bisa menulis HTML biasa ditambah directive untuk logika ringan. Beberapa directive penting:

  • {{ $nilai }} → menampilkan data sekaligus otomatis meng-escape HTML (aman dari XSS).
  • @csrf → menyisipkan token CSRF untuk melindungi aplikasi dari serangan Cross-Site Request Forgery. Wajib ada pada setiap form POST/PUT/DELETE.
  • @method('PUT') → "menipu" method HTTP. Form HTML hanya mendukung GET dan POST, padahal Laravel punya route PUT/PATCH/DELETE. Directive ini menambahkan hidden input _method agar Laravel memperlakukannya sebagai PUT/DELETE.
  • @forelse → perulangan yang punya blok @empty untuk menangani kondisi data kosong.
<form action="{{ route('mahasiswa.destroy', $mhs->id) }}" method="POST">
    @csrf
    @method('DELETE')
    <button type="submit">Hapus</button>
</form>

@forelse ($mahasiswa as $mhs)
    <tr>
        <td>{{ $loop->iteration }}</td>
        <td>{{ $mhs->nama }}</td>
    </tr>
@empty
    <tr><td colspan="7">Belum ada data mahasiswa.</td></tr>
@endforelse

Jelaskan bagaimana proses login bekerja di project ini. Tuliskan contoh method login() pada AuthController dan jelaskan fungsi Auth::attempt() serta session()->regenerate().

Jawaban

Proses login project ini:

  1. User mengisi email & password pada form (route /login).
  2. Data divalidasi, lalu dicek dengan Auth::attempt($credentials).
  3. Jika cocok → session di-regenerate dan user diarahkan ke menu pertama yang boleh diaksesnya.
  4. Jika gagal → muncul pesan "Email atau password salah".
public function login(Request $request): RedirectResponse
{
    $credentials = $request->validate([
        'email'    => ['required', 'email'],
        'password' => ['required'],
    ]);

    if (Auth::attempt($credentials, $request->boolean('remember'))) {
        $request->session()->regenerate();   // cegah session fixation

        return redirect()->intended(auth()->user()->firstAccessibleMenuUrl());
    }

    throw ValidationException::withMessages([
        'email' => ['Email atau password salah.'],
    ]);
}
  • Auth::attempt() mencocokkan email & password (password otomatis dicek terhadap hash) dan bila berhasil otomatis "mengenali" user pada session.
  • session()->regenerate() membuat ID session baru setelah login untuk mencegah session fixation attack.
  • redirect()->intended() mengarahkan user ke halaman yang tadinya ingin dibuka; pada project ini defaultnya ke firstAccessibleMenuUrl().

Apa yang dimaksud dengan RBAC (Role-Based Access Control)? Jelaskan konsep Role dan Permission, serta bagaimana penerapannya di project ini (termasuk RBAC berbasis menu).

Jawaban

RBAC adalah pengaturan hak akses berdasarkan peran. Di project ini memakai package spatie/laravel-permission.

  • Permission → izin spesifik, misalnya lihat-data, tambah-data, atau permission menu seperti menu-mahasiswa.
  • Role → kumpulan permission yang diberikan ke user. Contoh: role admin mendapat semua permission, role mahasiswa hanya lihat-data + menu-jadwal-kuliah.

Penerapannya:

  • Model User memakai trait HasRoles.
  • Middleware membatasi route: role:admin dan permission:menu-mahasiswa (alias didaftarkan di bootstrap/app.php).
  • RBAC berbasis menu: daftar menu disimpan di config/menu.php, dan menu hanya ditampilkan jika user punya permission-nya.
// config/menu.php
'mahasiswa' => ['label' => 'Mahasiswa', 'permission' => 'menu-mahasiswa', 'route' => 'mahasiswa.index'],

// resources/views/partials/nav.blade.php
@foreach (config('menu') as $menu)
    @can($menu['permission'])
        <a href="{{ route($menu['route']) }}">{{ $menu['label'] }}</a>
    @endcan
@endforeach

// routes/web.php
Route::middleware('permission:menu-mahasiswa')->group(function () {
    Route::resource('mahasiswa', MahasiswaController::class)->only(['index', 'show']);
});

Kunci: menu yang muncul di navigasi & route yang bisa diakses sama-sama dikunci oleh permission. Jadi selain disembunyikan di UI, akses langsung lewat URL pun tetap ditolak.

Apa fungsi Seeder pada Laravel? Mengapa seeder sebaiknya bersifat idempotent (aman dijalankan berulang), dan bagaimana contohnya pada project ini?

Jawaban

Seeder adalah class untuk mengisi data awal/awal aplikasi ke database, misalnya role, permission, dan user default. Dijalankan dengan php artisan db:seed atau php artisan migrate --seed.

Seeder dibuat idempotent (menjalankan dua kali tidak menggandakan data) dengan firstOrCreate(). Jadi seeder aman dijalankan berulang tanpa membuat data duplikat — penting agar tidak terjadi error unique constraint.

class RolePermissionSeeder extends Seeder
{
    public function run(): void
    {
        app(PermissionRegistrar::class)->forgetCachedPermissions();

        // idempotent: hanya dibuat jika belum ada
        $roleAdmin = Role::firstOrCreate(['name' => 'admin']);
        $roleAdmin->syncPermissions(['lihat-data', 'menu-mahasiswa', 'menu-dosen']);

        $admin = User::firstOrCreate(
            ['email' => 'admin@example.test'],   // kunci pencarian
            ['name' => 'Administrator', 'password' => 'password'] // data jika belum ada
        );
        $admin->syncRoles(['admin']);
    }
}

Bagaimana cara menampilkan data dengan pagination? Jelaskan juga apa itu Eager Loading (with()) dan masalah N+1 query yang dihindarinya.

Jawaban

Pagination membatasi jumlah data per halaman. Di controller digunakan paginate(10), sedangkan di view ditampilkan link halamannya dengan ->links().

  • withQueryString() menjaga parameter filter pada URL tetap ikut saat pindah halaman.
// Controller
public function index(): View
{
    $mahasiswa = Mahasiswa::with('kelas')   // eager loading relasi kelas
        ->orderBy('id')
        ->paginate(10)
        ->withQueryString();

    return view('mahasiswa.index', compact('mahasiswa'));
}

// View (mahasiswa/index.blade.php)
{{ $mahasiswa->links() }}

Eager Loading memuat relasi sekaligus di awal, bukan satu per satu saat dipanggil di dalam loop. Tanpa with('kelas'), setiap baris tabel akan menembak query baru ke database (N+1 problem) — 1 query untuk daftar mahasiswa + N query untuk masing-masing kelasnya.

// Tanpa eager loading → N+1 (boros query)
$mahasiswa = Mahasiswa::paginate(10);

// Dengan eager loading → hanya 2 query total
$mahasiswa = Mahasiswa::with('kelas')->paginate(10);
