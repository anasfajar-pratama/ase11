# Taste — User Preferences
- Communicates in Indonesian and expects replies in Indonesian. Confidence: 0.85
- When working on Laravel projects, wants every artisan/composer command that was run recorded into a `catatan.md` file (for reference). Confidence: 0.9
- Produces teaching material ("bahan ajar"): wants a step-by-step implementation module written as a self-contained HTML file that includes the implementation steps plus lists of new files and changed files. Confidence: 0.9
- In those HTML modules, code blocks (`<pre><code>`) should be made non-copyable via `user-select: none` (with vendor prefixes); inline `<code>` in prose/tables stays selectable. Confidence: 0.8
- In those HTML modules, expects the *complete* source code of new/changed files to be embedded (HTML-escaped in `<pre><code>` blocks), not merely a description or a partial snippet; will ask/check for missing files' source (e.g. flagged that `login.blade.php` / `style.blade.php` source was absent, and later that the new migration file's source was missing). This also applies to framework-generated files such as `vendor:publish` migrations — they must be shown in full with proper escaping (`<?php`, `->`, `&&`) and inserted at the step where they are created. Confidence: 0.95
- Prioritizes functionality over appearance in teaching code ("fokus di fungsi bukan tampilan"): UI should be simple and tidy, using only as much CSS as necessary and no extra CSS frameworks. Confidence: 0.85
- Prefers access control modeled per menu/feature (each menu = a permission assigned to roles) so which menus each role sees is *data* configurable from the admin UI, not hardcoded (`role:admin`-style checks) in code. Confidence: 0.65
- For restricted areas, hiding the navigation link is not enough — the route/URL must also be enforced (direct URL access denied with 403); UI hiding and route blocking go together. Confidence: 0.65
- Prefers to consolidate teaching modules into a *single* HTML file rather than many separate ones (to avoid confusion / "supaya tidak pusing"): merge related modules into one document with a unified TOC and one combined new/changed-file table, show shared files (e.g. `routes/web.php`, `nav.blade.php`) only once in their final version to avoid duplicated code, and delete the superseded module files rather than leaving duplicates around. Confidence: 0.75
- The file inventories in those HTML modules must be exhaustive: every new and changed file listed explicitly as its own row (no brace-grouping like `views/{a,b,c}/index.blade.php`, no merged `composer.json / composer.lock` rows), verified against `git status` with an automated cross-check that each path literally appears in the HTML — a missed file is considered fatal for teaching material. Confidence: 0.9
- Also produces assessment material (e.g. UTS exam question sets) as a standalone HTML file derived from the user's own project: straightforward, concept/fundamental questions whose answers mix a prose explanation with concrete code examples taken from that project. Confidence: 0.6
- Wants the prose/theory documentation written in Indonesian with a casual but still informative tone ("bahasa yang santai tapi tetap informatif") — analogy-driven explanation, not stiff academic wording — and often as a separate `.md` theory document (e.g. `libraryupload.md`) accompanying the HTML lecture module. Confidence: 0.75
- Lecture material is delivered incrementally per meeting ("kita lanjut perkuliahan ya, materi kali ini tentang …") and must match the established style/structure of the project's earlier modules rather than inventing a new format. Confidence: 0.7
- Each module must include, besides the steps and full source: a per-part **code analysis** ("analisa code") explaining *why* each piece is needed, and **screenshots of the feature actually implemented and running in this project** (with captions), not mockups. Confidence: 0.8
- Modules end with student practice exercises ("soal … untuk jam terbang"): apply the same pattern to another CRUD/feature, with explicit numbered requirements, point weights/rubric, and submission tips. Confidence: 0.75
- In those exam sets, wants at least one detailed, multi-part *practical* question (e.g. "build a Laravel project from scratch up to working CRUD, step a–g"), with explicit numbered requirements (install, database config, migration/model, routes/controller, validation, views, testing), a full "kunci / langkah pengerjaan" answer section, and scoring points; it should sit as Soal 1 with the concept questions renumbered after it. Confidence: 0.55
